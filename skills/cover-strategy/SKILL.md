# 标题与封面承诺检查

版本：v0.1 · 状态：draft · [许可](../../LICENSE)

## 1. 解决什么问题

标题和封面给了点击理由，正文却没有回答读者因此产生的问题。本方法核对承诺与内容是否对应，不生成标题模板、配色或行业词表。

## 2. 检查表

1. 标题与封面分别承诺了什么？用一句话写出读者以为会得到的答案、方法或解释，不能只写“吸引注意”。
2. 这条内容面向谁、处理什么情境？从可见文字中指出依据，不能靠作者另外解释才知道。
3. 读者点进来会期待看到什么？将合理期待逐项写明，核对标题有没有扩大内容范围。
4. 每项承诺在正文第几段或第几页兑现？指出实际位置和内容；“后面会讲”或重复标题不算兑现。
5. 正文给了什么依据、步骤或条件？检查它能否回答承诺的问题，不能把结论换一种说法当作解释。
6. 标题省略了哪些会改变理解的条件？核对正文是否及时说明，是否出现用局部材料暗示普遍结果的情况。
7. 读者看完得到的东西是否与点进来的理由一致？若主要内容、结尾或下一步转向别的问题，指出转换发生在哪里。

## 3. 使用方法

输入发布标题、封面文字、完整正文及读者背景。逐条回答，用原文或具体段落位置作依据；答不上来就修改承诺或补齐正文，再核对一次。缺少正文时只能列出待查项，不能宣告已经兑现。

输出逐题回答、对应证据和需要修改的位置。全部有对应依据时，可写“本轮未发现承诺脱节”；这句话不代表作品已通过事实核验或已获发布授权。不要为了让检查通过补造案例、结果或来源。

## 4. 已知限制

不适用于纯信息型卡片；这类内容往往在同一张图内完成信息交代，没有封面到正文的兑现关系。本检查也不涉及视觉审美判断，不评价字体、配色、人物、构图或图片是否好看。

只能依据输入推断合理期待，不能代替真实读者反馈。没有平台数据时不能判断点击表现；有数据也不能仅凭这一张检查表归因。本模块尚未完成独立行为测试，保持 draft，见[验证状态](../../docs/validation-status.md)。
