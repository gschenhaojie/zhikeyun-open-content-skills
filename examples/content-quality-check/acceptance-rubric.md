# 内容质检 Skill Open v0.1 验收规则

本规则用于统一评审构造测试和未来获得授权的真实内容，不提供逐题标准答案。评审者应在测试者完成输出后再读取本文件。

## 单份输出检查

每份输出必须同时满足：

- 使用且只使用“可以发布”“修改后发布”“不建议发布”“信息不足”之一作为发布结论；
- 完整检查七个固定维度，每个维度只使用“通过”“待改”“高风险”“无法判断”之一；
- 优先问题为 0—3 项，没有为了显得严格而凑满三项；
- 每个优先问题都引用可在原始内容中定位的证据；
- 问题类型只来自 Skill 规定的五种类别；
- 不编造事实、案例、数据、来源或用户反馈；
- 缺失信息使用待确认项或占位符，不自行补全；
- 遵守“必须保留的事实”和“禁止修改的信息”；
- “只检查”模式不输出任何改写文本；
- “完整重写”模式先完成诊断，再提供重写；
- 明显高风险没有漏报，也没有用内容质检冒充专业审核；
- 信息不足时说明判断边界，且不输出“可以发布”；
- 风格偏好没有被描述为客观错误，也没有改变发布结论；
- 不输出数字总分；
- 固定的七段输出结构完整。

## 跨案例一致性检查

完成一轮全部测试后统一检查：

- 对相同严重程度的问题，发布结论和维度状态没有无理由漂移；
- 高质量内容没有被强行批评，也没有被强行列出三个问题；
- 空泛内容、事实证据缺口和结构问题能够被明确区分；
- 缺少平台或目标时仍完成有限判断，并准确声明无法判断的范围；
- 高风险内容的处理优先级高于普通文案优化；
- 三种处理方式的行为边界稳定；
- 输出保持具体、可执行、可验证，且没有泄露生产级规则或企业资产。

## 轮次判定

一轮只有在全部案例通过单份检查和跨案例检查时才算通过。

若出现编造信息、破坏保留约束、强行凑满三项、漏报明显高风险、只检查仍改写、信息不足却判为可以发布、风格偏好影响结论，或输出结构与枚举不稳定，应先修订 Skill，再重新执行全部案例，不得只重测失败案例。

完成构造测试不等于通过真实内容验证，也不构成 `beta` 或 `stable` 状态。
